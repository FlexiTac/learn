# Learn FlexiTac in two languages (English, 简体中文)

The site has two languages: **English**, the default, and **Simplified Chinese** (`zh`, shown as `zh-CN`). The globe
button in the sidebar, directly above Theme, switches between them. This file is the contract that every part of the
site follows: the lessons, glossary, pages, widgets and figures. The words themselves follow the term sheet,
[`i18n-terms-zh.md`](./i18n-terms-zh.md). Read it before you write any Chinese.

**Rule 0: English stays exactly as it is.** Chinese is laid over the English and never replaces it. When a Chinese
text is missing, the English shows instead, never a blank. With the site in English, every page renders
pixel-identical to the English-only site, except for the globe button itself.

## How the language is chosen

| What | Where |
|---|---|
| state | `src/i18n/lang.ts`: `lang()`, `isZh()`, `setLang(l)`, `toggleLang()`, `onLang(fn)` (returns an unsubscribe), `initLang()` (called once in `src/main.ts` before anything renders) |
| saved | in the site's one localStorage record (`src/state/store.ts`, key `learn-flexitac:v1`, field `lang`). Every access there is wrapped in try/catch, so the site still works when storage is blocked (it just forgets the choice). "Reset my progress" keeps it. |
| address | `?lang=zh` / `?lang=en`, before the `#` (`/?lang=zh#/lesson/one-frame`). It wins over the saved choice and is saved like a click. While a `?lang=` is in the address, switching keeps it in step (`history.replaceState`). Also accepted: `zh-CN`, `zh-Hans`, `cn`, `en-US`. |
| default | English. The browser's language is *not* used. |
| `<html>` | `lang="en"` or `lang="zh-CN"`, plus `data-lang="en|zh"`. CSS keys off `:lang(zh)` (see CSS below). |

A switch never reloads the page:

- **The shell** (sidebar, header, progress card) repaints its words in place, so focus stays on the globe.
- **The home, lesson-list, glossary and about pages** are drawn again at the same scroll position. The glossary
  keeps its filter text.
- **A lesson** keeps everything that is not words: the guided step on show and its Show me, the figure's pose (the
  figure is not reloaded), the widget and its state, the open tab, the reading fold, the code card's values and
  output, and an open detail window. It repaints the panel text, the steps bar, the strip, the code card's labels
  and the details chrome (`src/views/lesson.ts`, the `onLang` block).

## The string table (UI chrome and page texts)

`src/i18n/strings.ts`: `t(key, vars?)` returns the string in the current language. It uses the Chinese line when
the site is in Chinese and that line exists, and the English one otherwise. `{name}` placeholders are filled from
`vars`. Values are trusted, authored HTML. Vars are **not** escaped, so pass `esc(userText)`.

| File | What | Who fills the Chinese |
|---|---|---|
| `src/i18n/en/ui.ts` / `src/i18n/zh/ui.ts` | UI chrome: sidebar, header, numbering ("Lesson {no}" → 「第 {no} 课」), tabs, steps bar, quiz, strip, code card, details window, badges, source chips, glossary/lessons/home/about chrome | done (plumbing) |
| `src/i18n/en/pages.ts` / `src/i18n/zh/pages.ts` | page texts: home hero, lesson-list lede, about page | the pages translator |

The keys are typed. `t("nav.home")` type-checks, and a typo does not. The Chinese tables are
`Partial<Record<key, string>>`, so a missing key falls back to English. To add a string, put the English in `en/*.ts`,
the Chinese in `zh/*.ts`, and call `t()` where it shows. Keep every `{placeholder}` of the English line in the Chinese
one.

Two helpers for code that keeps its words next to itself (widgets, lesson `run()` output):

```ts
import { strings, tx } from "../i18n";
tx("Press", "按压")                         // one string: Chinese in Chinese, else the English
tx("{n} pressed", "{n} 个被按下", { n })    // with placeholders
const S = strings(                          // a table: S() is the current language's (missing keys -> English)
  { press: "Press", ready: "Ready" },
  { press: "按压", ready: "就绪" },
);
el.textContent = S().press;
```

## Lessons: `src/lessons/zh/<same file name>.ts`

Each lesson's Chinese is its own file, named like the English lesson file, and exports a `LessonZh`
(`src/i18n/localize.ts`):

```ts
// src/lessons/zh/09-one-frame.ts
import { COLS, ROWS } from "@shared/data/constants.mjs";   // numbers come from the shared data, as in the English file
import type { LessonZh } from "../../i18n/localize";

export const zh: LessonZh = {
  id: "one-frame",                 // the English lesson's id (required: the file is found by it)
  title: "一帧数据",
  kicker: "读取板",
  lede: `……`,
  features: [{ title: "逐行读取", text: "……" }, , { text: "……" }],   // by place; a hole or undefined keeps the English
  overview: `<p>……<dfn data-term="frame">帧（frame）</dfn>……</p>`,
  specs: [{ label: "帧大小", note: `AA 55 + ${ROWS * COLS} 个读数` }],  // by place in the English specs list
  steps: [{ title: "插上传感垫", text: "……" }],                         // by place
  quiz: [{ q: "……", choices: ["……", "……", "……", "……"], why: "……" }],  // choices by place: keep the order (answer index is the English one)
  wiring: { intro: "……", rows: [{ note: "……" }], foot: "……" },
  parts: { rows: [{ name: "……", qty: "……", note: "……" }] },
  code: { caption: "……", notes: ["……"], params: [{ label: "……" }] },   // the code itself never changes
  media: [{ alt: "……", caption: "……" }],
};
```

- Only words. Everything else comes from the English lesson: ids, acts, answers, code, numbers, badges, sources. You
  never copy logic.
- Every field is optional, and lists go by place. An **empty string counts as missing**, so a half-filled file never
  blanks a text.
- `loc(lesson)` returns the lesson in the current language (`loc(lesson, "zh")` forces Chinese). In English it is the
  lesson object itself, and in Chinese a memoised merged copy. The views, steps bar, quiz, strip, details window and
  code card all render `loc(lesson)`. Logic keeps using the English `lesson`.
- **Defined terms:** write `<dfn data-term="<glossary id>">中文（English）</dfn>`. `data-term` names the glossary
  entry, so the popover finds it whatever the words, and shows the Chinese name and definition. A `<dfn title="…">`
  with no glossary entry shows its title: translate the title.
- Keep each step text to **3 lines** at 1366–1440 px windows. The bar takes its longest step's height.
- **Specs** rows made by `fact()` know which shared fact they show (`spec.fact`). For a row the lesson's Chinese
  leaves out, the Chinese comes from `src/content/facts.zh.ts`: the fact's own words (`FACTS_ZH[key].note | value`,
  plus `UNITS_ZH` for the counted nouns `formatValue()` writes: "384 taxels" → 「384 个触觉像素」), then `SPECS_ZH`,
  keyed by the English text exactly as the row shows it (every label, and the values and notes a lesson wrote itself,
  for all 12 lessons), then `FACTS_ZH[key].label`. So every Specs tab is Chinese even before its lesson's file says
  anything; a lesson's own `specs` entry still wins. Give `value` only where the English value has words.
- A lesson's `code.run()` output and its own helper strings: use `tx()` / `strings()` in the lesson file.

Start a file with the check script's scaffold, which prints every English text as a comment above an empty slot:

```bash
node scripts/i18n-check.mjs --scaffold 09-one-frame > src/lessons/zh/09-one-frame.ts
```

## Sections, glossary, facts

| File | Shape | Used by |
|---|---|---|
| `src/lessons/zh/_sections.ts` | `SECTIONS_ZH: { [n]: { title?, blurb?, chapters?: [{ title?, text?, alt? }] } }`. Chapters go by place. | home cards and section titles, lesson list (`locSection`) |
| `src/content/glossary.zh.ts` | `GLOSSARY_ZH: { [termId]: { term?, aka?, def? } }`. Leave `term` out for names that stay English (Velostat, FPC). | glossary page (Chinese name with the English beside it, English order, filter matches both), `<dfn>` popovers (`locTerm`) |
| `src/content/facts.zh.ts` | `UNITS_ZH`, `FACTS_ZH: { [factKey]: { label?, note?, value? } }`, `SPECS_ZH: { [English text]: 中文 }` (all filled) | Specs rows (`locSpec`) |
| `src/content/sources.ts` | source chips: names from `chip.*` (UI strings); in Chinese the detail after a name (Fig 3a → 图 3a, Step 2 → 第 2 步, BOM item 4 → BOM 第 4 项) and `RAW_ZH` for the few sources with no chip name | Specs rows, details window |

## Widgets (`src/widgets/*.ts`)

Every widget gets two more things in its context (`WidgetCtx`, and `LessonCtx` for a lesson's `run()`):

```ts
ctx.lang(): "en" | "zh"
ctx.onLang((l) => { /* repaint your words */ }): () => void   // ends with the lesson too
```

- Put your words in `strings(en, zh)` / `tx(en, zh)` (above). Paint them from the table, and again in `ctx.onLang`.
- **Do not remount and do not reset state** on a switch. Keep the animation, the pressed spot and the slider values.
  Repaint text only, then lay out again if your layout measures text. The stage card (`src/ui/stagecard.ts`) already
  re-runs its fit on a switch, and a demo card's chrome (its × button) is done by `src/ui/demo.ts`.
- Unsubscribe in `destroy()` (the subscription also ends with the lesson).
- `ctx.lesson` is the English lesson. For its words in the current language use `loc(ctx.lesson)`.
- Canvas or SVG labels count too: they are words a learner sees.
- Check at 1366×768, 1440×900 and 1920×1080 that the Chinese labels fit. Chinese is usually shorter than English
  but taller per line.
- **Run output.** A widget whose `run(params)` returns lines for the code card's console should also export
  `say(params)`: the same lines in the language on show, without touching the widget (`frame-runner`, `heatmap-lab`).
  A lesson's own `code.run` that only computes its lines sets `pureRun: true` (`12-build-your-own`). On a switch the
  console then shows the last Run's lines in the new language. Without them it is cleared rather than left in the
  other language (`src/ui/codecard.ts` `relabel`, `src/views/lesson.ts` `onSay`).

## Pictures with words in them (covers and thumbnails)

Some home covers and lesson thumbnails are pictures of a figure or a card, and their labels are part of the picture.
Each of those has a Chinese picture beside the English one, named `<name>-zh-<theme>.webp`. The English files are
never rewritten for this, and a picture without words has one file for both languages.

| Pictures | Made by | Chosen in |
|---|---|---|
| `public/media/covers/{mount,grasp,points,springs,loop}-zh-<theme>.webp` | `node scripts/covers.mjs --port <your vite dev port> --lang zh` (it serves `scripts/covers.html?…&lang=zh`) | `src/views/home.ts` `ZH_COVERS` |
| `public/thumbs/{L09,L10,L11}-zh-<theme>.webp` | the same run of `covers.mjs --lang zh` | `src/ui/thumbs.ts` `ZH_THUMBS` |
| `public/thumbs/{L01,L04}-zh-<theme>.webp` | `node scripts/thumbs.mjs --lang zh` (the figure pages with `?record&lang=zh`) | `src/ui/thumbs.ts` `ZH_THUMBS` |
| `public/media/cover/cover-zh-<theme>.{webm,mp4,webp}` (Section 1's pad loop) | `bash ../flexitac-anatomy/film/cover-src/make-cover-zh.sh` (the site's synced Fig 1 pages with `&lang=zh`, the same shot and crop as `make-cover.sh`) | `src/views/home.ts` `LOOPS.pad` |

The home page and the lesson list draw themselves again on a switch, and a lesson's strip is built again, so the
pictures follow the language. When a figure or card changes its words, make its Chinese pictures again too.

## Figures (`../flexitac-anatomy/figures/<fig>`)

The site's side is done in `src/figure/FigureHost.ts`.

- **On load**, the iframe URL gets `&lang=zh` when the site is in Chinese. **Nothing** is added in English, so every
  English URL, build and `?record` film stays byte-identical.
- **Live switch:** `host.setLang(l)` sends `{type:'ft:act', name:'lang', arg:'en'|'zh'}` **if the figure declared
  `lang` in its `ft:ready` actions**. This act is not kept in the act history, so it is never replayed. If the figure
  declared no `lang` act but its `ft:ready` carries a `lang` field (it reads `?lang=` but cannot switch live), the
  host reloads it like a theme switch: the act history replays the pose. A figure that knows neither is left alone
  until its next load.
- `ft:ready` should report `lang: 'en'|'zh'`. If it reports a language other than the site's and declares `lang`,
  the host sends the act at once.

What a figure must do for Chinese:

1. Read `?lang=zh` at load (`new URLSearchParams(location.search).get("lang")`). Draw every visible word in Chinese:
   labels, hints, readouts, Details intros, facts, the all-labels cards, chips and the viewbar's titles. Keep English
   the default. Draw nothing differently when there is no `lang` param: English and `?record` determinism must stay
   byte-identical.
2. Declare `lang` in `ft:ready`'s `actions` and report `lang` in `ft:ready`. On `ft:act lang`, repaint the words in
   place. Keep the pose, camera, selection, feel/teleop state and the idle-tour state. Then post `ft:parts` again and,
   with a part picked, `ft:pick` with its record in the new language. The site's detail window follows (it re-renders
   on a new `intro`). `ft:state.readout` is in the new language from then on.
3. Put the Chinese in `<fig>/zh.mjs`, which the check script reads:

   ```js
   // ../flexitac-anatomy/figures/pad/zh.mjs
   export const ZH = {                    // UI strings, keyed by the English exactly as the figure shows it;
     "Click a part · drag to pan": "点击部件 · 拖动平移",   // ${x} in the source matches {name} in a key
     "Pressing at drive {d}, sense {s}": "按压位置：驱动线 {d}，感应线 {s}",
   };
   export const PARTS_ZH = {              // parts.mjs words by part id; facts by place
     lam_t: { title: "顶层覆膜", chip: "顶层覆膜", short: "……", intro: "……", facts: [{ label: "厚度", value: "资料中未给出" }] },
   };
   ```

   How the figure uses them is up to its build (`build.mjs` inlines them, and `live.js` looks words up with a small
   `T(en, vars)`). The check script only needs the two exports.
4. CJK text in the SVG and in the HTML chrome: use the same font stack as the site (`"PingFang SC", "Hiragino Sans
   GB", "Noto Sans CJK SC", "Noto Sans SC", "Microsoft YaHei", sans-serif` after the Latin faces). Do not upper-case
   or letter-space Chinese. Check that labels and cards do not overflow.
5. Figure gates after any figure change: `node build.mjs` (+ `--light`), `--audit` → "audit passed",
   `node ../anatomy/scripts/lines.mjs` on both pages → "line ends: 0", `?record` determinism (English unchanged!),
   `npm run sync-figures`.

## CSS (`src/styles/i18n.css`)

- `:root:lang(zh)` puts a CJK sans after the Latin faces in both `--sans` and `--mono`, so numbers, code and English
  names look as they do in English and a mono kicker with Chinese never falls back to a serif. `--sans-cjk` is the
  CJK stack alone.
- Every element whose language is Chinese drops `text-transform` and `letter-spacing` (`!important`: the kicker and
  label styles all over the site set both). Something that must keep the English look inside a Chinese page carries
  `lang="en"` (the brand name does).
- No synthetic italics: `i`, `em`, `cite`, `dfn` are upright, and so are the site's own italic notes (`.empty`: an
  empty tab's or an empty search's note; `.wp-lab-ng`: a layer whose thickness is not given; the layer inspector's
  guesses). Code comments keep their italics. A new italic style for words needs its class in that rule. Running text uses line-height 1.65, headings at least
  1.3, and the sidebar's tiny mono labels are 11 px CJK sans.
- A widget with its own CSS may add `:lang(zh)` rules of its own (e.g. `.my-label:lang(zh) { font-size: 12px }`).
- The lesson strip's two-line titles use `word-break: keep-all`, so they break at a title's spaces and punctuation,
  never inside a word (“把 FlexiTac / 装到机器人上”, not “……机器 / 人上”). Keep every piece between two break points
  short enough for one line of a strip card (about 8 characters).

## The check script

```bash
node scripts/i18n-check.mjs              # everything that has no Chinese yet, grouped
node scripts/i18n-check.mjs --summary    # one line per lesson / page / widget / figure
node scripts/i18n-check.mjs --lesson one-frame        # one lesson (id or file name)
node scripts/i18n-check.mjs --only glossary,sections  # groups: ui pages sections lessons glossary widgets figures
node scripts/i18n-check.mjs --widget sim-loop         # one widget file
node scripts/i18n-check.mjs --figure pad              # one figure
node scripts/i18n-check.mjs --all        # also the widgets and figure (Fig 2) no lesson uses today
node scripts/i18n-check.mjs --json       # machine-readable
node scripts/i18n-check.mjs --scaffold 09-one-frame   # a zh lesson file to start from
node scripts/i18n-check.mjs --strict     # exit 1 when anything is left
```

It loads the content through Vite exactly as the site does, then lays the Chinese over it. A text is listed when it
is still the English one **and** has English words in it. Numbers, units, code, and the names that stay English
(term sheet) do not count. Lessons also get a "STALE" line when a Chinese list is longer than the English one (a step
or question was removed). For widgets, the site's UI code and figures it reads the source. It lists English-looking
strings that are not inside `t()`, `tx(en, zh)` or `strings(en, zh)`, or that are not keys of the figure's `zh.mjs`.
That part is a heuristic: read the list as candidates.

For a figure, everything `parts.mjs` makes is read as data (`PARTS`, Fig 3's `SHIFT` record and the all-labels
`CARDS`), against `PARTS_ZH` and `CARDS_ZH`. A source string in `parts.mjs` or the figure's scripts counts as done when
it is part of one of those texts (its `${}` slots matched as wildcards). A fact's `src` stays English by contract. The
layout audit's reasons (`fanWhy = …`, `ALL.why = …`, `last = …`), the labels a helper throws with (`idx(v, n, "…")`)
and the words `parts.mjs` checks its facts still say (`says(…)`, `nanoSays(…)`) are skipped, as are CSS declarations
(`font-size:{}px`). So `--strict` exits 0 on the finished site, and can be used as a gate.

## Verify a translation

1. `npx tsc --noEmit`.
2. Build to a temp folder and serve it on your own port: `npx vite build --outDir <tmp>` and
   `npx vite preview --outDir <tmp> --port <89xx> --strictPort`. Never use the dev server on :5173.
3. Open `?lang=zh#/lesson/<id>` at 1920×1080 and 1440×900 (light and dark) and at 1366×768 (light). Walk every
   step: the step text should take ≤ 3 lines, nothing should overflow, and the dfn popovers should open. Then click
   the globe there, mid-step: the step and the pose stay.
4. Switch back to English and check that it is unchanged.
5. `node scripts/i18n-check.mjs --lesson <id>` should list nothing you meant to translate.
